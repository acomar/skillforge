# Checklist de validação

Antes de considerar o mapa utilizável:

- [ ] Eventos representam fatos no passado.
- [ ] A sequência principal pode ser narrada ponta a ponta.
- [ ] Caminhos alternativos e falhas relevantes foram explorados.
- [ ] Eventos importantes têm causa conhecida ou hotspot explícito.
- [ ] Commands têm ator, política ou origem identificável quando conhecida.
- [ ] Regras críticas estão explícitas.
- [ ] Sistemas externos estão distinguidos do domínio.
- [ ] Termos conflitantes foram registrados.
- [ ] Hipóteses não aparecem como fatos.
- [ ] Bounded contexts são candidatos até validação.
- [ ] Elementos relevantes possuem evidência/origem.
- [ ] Hotspots e perguntas abertas estão priorizados.
- [ ] O mapa distingue As-Is de qualquer sugestão de To-Be.
- [ ] O nível de detalhe é coerente com Big Picture, Process Level ou Software Design.
- [ ] Um especialista de domínio conseguiria contestar e corrigir o mapa.
